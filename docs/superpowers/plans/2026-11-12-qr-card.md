# QR 카드 셀프 제작 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사장님이 앱에서 매장 출퇴근 QR 카드(스탠드 A6 / 스티커 80×80mm)를 레이아웃·색·문구·로고로 꾸미고 PDF·PNG로 받는다. 언제든 다시 뽑을 수 있게 QR 원문을 암호화해 저장한다.

**Architecture:** 서버는 QR 원문을 AES-256-GCM으로 암호화해 `StoreQrToken.tokenCiphertext`에 두고 Owner에게만 풀어 준다. 디자인은 `StoreQrDesign`(매장당 1행)에 저장한다. 카드는 순수 레이아웃 함수(mm 좌표)를 캔버스에 그려 PNG를 만들고, PDF는 그 PNG를 실제 크기 페이지에 넣는다. 화면은 한 페이지(미리보기 + 컨트롤, 자동 저장).

**Tech Stack:** Next.js 15 Route Handler(`defineRoute`), Prisma 6 + raw SQL 마이그레이션, Node `crypto`, `qrcode`(기존), `pdf-lib`(신규), Vitest + PGlite, Seed Design, webviewkit 스택.

**Spec:** `docs/specs/qr-card/README.md` (정본, 특히 §3·§4·§8). 관련 `docs/specs/store/README.md` §5.

## Global Constraints

- 암호문 형식 `v1.<iv base64url>.<ciphertext+tag base64url>`, AES-256-GCM, iv 12바이트, 키 `QR_TOKEN_ENC_KEY`(32바이트 base64). production에서 키 없으면 `INTERNAL`, 그 밖은 고정 개발 키 (`assertDevFallbackAllowed('QR_TOKEN_ENC_KEY')` 패턴).
- 출퇴근 판정은 지금처럼 `tokenHash`만 쓴다. DB에 원문 평문을 두지 않는다.
- QR URL = `${process.env.APP_ORIGIN ?? req.nextUrl.origin}/p/<원문>`.
- 모든 QR·디자인 API는 Owner만 (`STORE_ADMIN`). `GET /qr`는 `Cache-Control: no-store`.
- 레이아웃 `STAND` 105×148mm, `STICKER` 80×80mm. QR 최소 스탠드 60mm·스티커 50mm, 오류 정정 M. 스티커에는 `message`를 그리지 않는다.
- 색 프리셋 키: `kok`, `kokFill`, `white`, `black`, `blue`, `green`. QR은 항상 흰 바탕 검정.
- `title` 1~20자, `message` 0~40자. 기본 `message` = `휴대폰 카메라로 찍고 출근·퇴근 버튼을 눌러 주세요`.
- 로고: 디코드 바이너리 200KB 이하, 매직바이트로 PNG·JPEG 판별. 클라이언트에서 긴 변 512px PNG로 줄여 올린다.
- PNG 300dpi: 스탠드 1240×1748, 스티커 945×945.
- 커밋 `feat: 한글 설명` + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, author `94547692+Ahnseungc@users.noreply.github.com`. 스펙이 바뀌면 같은 커밋에서 갱신. 코드 주석에 스펙 절.
- 완료 조건: `pnpm typecheck && pnpm test` 통과.

## Review Focus

1. **암호문이 깨졌거나 다른 키로 만든 경우** — 복호화 실패는 500 스택이 아니라 `url: null` + `console.error`로 재발급 안내가 떠야 한다. → Task 1 `잘못된 암호문이면 url null`.
2. **긴 한글 제목(20자)·긴 안내 문구(40자)** — 카드 밖으로 넘치지 않고 줄바꿈/축소된다. → Task 3 `20자 제목은 카드 폭 안에 들어간다`.
3. **가로로 아주 긴 로고(예 512×64)** — 비율을 유지한 채 로고 영역 안에 맞춘다. → Task 3 `넓은 로고는 비율을 지켜 영역 안에 맞춘다`.
4. **확장자를 png로 속인 GIF** — `QR_LOGO_INVALID`. → Task 2 `헤더가 png여도 GIF 바이트면 QR_LOGO_INVALID`.
5. **재발급 직후 디자인 화면 재진입** — 새 URL로 그리고 디자인은 그대로. → Task 1 `재발급하면 새 암호문, 디자인은 유지`.
