> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 정산 기간이 끝나면 직원별 임금명세서 초안을 만들고, 사장님이 확인·수정해 보내면 직원 앱에 FCM 푸시로 알린다. 근태가 바뀌면 정정본을 만든다.

**Architecture:** 계산은 DB를 모르는 순수 함수(`features/payslip/model`)로 두고, 서버(`features/payslip/server`)는 기존 정산 계산(`computePayroll`)을 불러 명세서와 동기화한다. 동기화는 **명세서 목록을 읽을 때와 일배치**에서 한다. 근태·근로조건 쓰기 서비스는 건드리지 않는다. 푸시는 `PushSender` 어댑터(dev 로그 / FCM)로 감싼다.

**Tech Stack:** Next.js 15 Route Handler + `defineRoute`, Prisma 6 + raw SQL 마이그레이션, Vitest + PGlite(`createTestDb`), Zod, Seed Design, Expo 58 + `@react-native-firebase/messaging`, `firebase-admin`.

**Spec:** `docs/specs/payslip/README.md` (정본). 배경은 `docs/specs/payroll/README.md` §3·§4.

## Global Constraints

- 금액은 원 단위 정수. 3.3%: 소득세 = `floor(gross × 0.03 / 10) × 10`, 지방소득세 = `floor(소득세 × 0.1 / 10) × 10`.
- 직원은 `SENT`·`SUPERSEDED`만 본다. `DRAFT`는 본인에게 `NOT_FOUND`.
- 수정·보내기는 Owner만. 조회는 Owner·`PAYROLL_READ`·본인. INACTIVE 본인도 자기 명세서 조회·열람 기록은 된다.
- `SENT`·`SUPERSEDED`는 불변. 보존: 퇴사 후 3년(삭제 로직 없음).
- 같은 `(membershipId, periodStart)`에 `DRAFT`는 최대 1개 (부분 유니크).
- 푸시 실패는 보내기를 롤백하지 않는다.
- 커밋 형식 `feat: 한글 설명` / `docs: …`, author `94547692+Ahnseungc@users.noreply.github.com` (워크트리 config 확인). 스펙이 바뀌면 같은 커밋에서 갱신 (`.cursor/rules/docs-spec-by-feature.mdc`).
- 코드 주석에 스펙 절 (`/** POST /payslips/:id/send — docs/specs/payslip §7 */`).
- 모든 작업 완료 조건: `pnpm typecheck && pnpm test` 통과.

## Review Focus

1. **정정본 만든 직후 사장님이 원래 DRAFT 금액을 고쳐 둔 경우** — 같은 기간에 `SENT` v1 + `DRAFT` v2가 있을 때 근태가 또 바뀌면 v3를 만들지 말고 v2를 갱신해야 한다. → Task 3 테스트 `정정 DRAFT가 있으면 새 버전을 만들지 않고 갱신한다`.
2. **동시에 목록을 두 번 열어 동기화가 겹치는 경우** — 부분 유니크 위반(P2002)을 삼키고 한 건만 남아야 한다. → Task 3 테스트 `동시에 동기화해도 DRAFT는 1건`.
3. **공제 방식을 3.3% → 4대보험으로 바꾼 DRAFT에서 지급액이 다시 바뀌는 경우** — 수기 공제 금액은 유지, 3.3% 줄은 남지 않아야 한다. → Task 2 테스트 `deductionType을 바꾸면 공제 줄 묶음을 갈아 끼운다`.
4. **퇴사(INACTIVE) 직원이 앱에서 마지막 명세서를 여는 경우** — `requireMembership`이 FORBIDDEN을 내면 안 된다. → Task 5 테스트 `INACTIVE 본인도 SENT 명세서를 본다`.
5. **기간 중 시급이 바뀐 직원** — 기본급 basis가 시급별 줄로 나뉘고 합계는 미리보기와 같아야 한다. → Task 2 테스트 `시급이 두 개면 basis가 두 줄`.
